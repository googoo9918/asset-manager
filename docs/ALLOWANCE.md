# 용돈 기록과 카드 전표 연결

`/allowance`에서 동구·윱니의 용돈을 별도로 기록합니다. 실제 자산·계좌 잔액이나 지출 분류를 변경하지 않습니다. 기록하지 않은 사용액은 알 수 없으므로 표시 금액은 **기록 기준 잔액**입니다.

## 전표 저장할 때

카드 → 이용내역/매출전표 가져오기 → 최종 등록 화면에서 전표마다 **용돈 반영: 안 함 / 동구 / 윱니**를 선택합니다. 기본값은 안 함입니다. 여러 전표를 체크하고 ‘선택한 전표에 적용’을 누를 수 있습니다. 다른 페이지에 선택한 전표에도 적용되며, 체크하지 않은 전표는 바꾸지 않습니다.

최종 확인에는 두 사람의 용돈 사용액도 표시됩니다. 기존 지출 등록·가져오기 중복 키·용돈 연결은 한 DB 트랜잭션으로 저장됩니다. 용돈 연결은 계좌 잔액을 추가로 차감하지 않습니다. 기존 체크카드 잔액 반영 선택은 그대로 적용됩니다.

이미 가져온 전표는 중복·확인 필요 필터에서 연결된 사람을 확인하고 **연결 저장**으로 변경하거나 ‘안 함’으로 해제할 수 있습니다. 거래를 다시 등록하지 않습니다. 하나의 원전표는 한 사람에게만 연결되며, 재수집·재저장으로 중복 반영되지 않습니다.

## 용돈 화면

- 상단 사람 선택과 조회 월로 확인합니다. ‘금액 추가’는 기본 800,000원이지만 수정할 수 있습니다. 자동 지급은 하지 않습니다.
- ‘사용액 추가’는 현금 사용·누락 지출 합계 등을 음수로 기록합니다. 환급·보정은 금액 추가로 기록합니다.
- 날짜·금액·사람·메모를 수정하거나 직접 입력한 내역을 삭제할 수 있습니다. 카드 연결은 사람 변경·연결 해제를 제공합니다.
- 월별 추가액·사용액, 이전 기록 잔액, 조회 월말 기록 기준 잔액을 표시합니다. 과거 기록은 다음 달로 이어지며 미래 월의 기록은 합산하지 않습니다.
- 이용일 기준으로 전표 전체 구매액을 반영합니다. 할부도 구매액을 한 번에 기록하며 카드 결제일·회차별로 나누지 않습니다.
- 원거래를 수정하면 수정된 날짜·금액을 반영합니다. 원거래가 취소되면 내역에 ‘합산 제외’를 표시합니다. KB에서 발견된 취소 전표는 기존 절차대로 원거래 취소를 확인·처리해야 합니다.
- 용돈 연결 해제·수동 내역 삭제는 용돈 기록만 비활성화합니다. 원거래와 계좌 잔액은 유지됩니다.

## 반영과 검증

기존 DB는 백업 후 `gradlew.bat migrateAllowance --offline`을 실행하고 서버를 재시작합니다. 신규 DB는 schema.sql에 포함됩니다. 전체 DB 백업에 용돈 기록도 포함됩니다.

- AllowanceServiceTest: 월별 합계·이월·사용자 구분, 원거래 수정/취소, 요청 재시도, 잘못된 입력
- KbImportServiceTest: 전표와 용돈 연결, 중복 저장 차단, 잘못된 사용자 사전 검증
- AllowanceIntegrationTest: ASSET_ALLOWANCE_DB_TEST=true일 때 격리 DB localhost:55441/billing_test에서 실제 트랜잭션, 중복 방지, 용돈 저장 실패 시 원거래 롤백, 계좌 잔액 보존 확인. 기존 애플리케이션 스키마가 필요합니다.
- tests/allowance-browser.cjs: +/− 입력·수정·연결 변경/해제, 검색, 15개 페이징, 소유자, 모바일
- tests/kb-incremental-browser.cjs: 전표별/일괄 선택, 기존 연결 변경, 최종 확인과 저장 요청
