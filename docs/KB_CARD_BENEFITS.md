# 카드 실적 구간·월별 혜택 관리

카드 화면에서 관리 카드 추가, 구간·혜택 설정, KB 동기화와 월별 적용 구간 선택을 제공합니다. 실적 관리가 필요한 카드만 등록합니다.

## 처음 한 번 설정

1. 관리 카드(예: StarB)와 KB 화면의 정확한 카드명(예: KB Star B카드)을 연결합니다.
2. 적용 시작월을 지정하고 각 구간의 이름·최소 인정 실적을 입력합니다.
3. 구간별 혜택 이름·월 한도·단위를 입력합니다. KB 받은 혜택명은 실제 표시명과 동일하게 입력합니다. 한 혜택에 여러 KB 항목이 포함되면 줄바꿈으로 추가합니다.
4. 구간·혜택 설정을 저장합니다. 다음 달에도 유지됩니다. 조건이 바뀌면 적용 시작월을 변경하여 새 버전으로 저장합니다.

입력한 최소 실적 이상인 가장 높은 구간을 적용합니다. 금액을 임의로 추천하거나 카드 상품 약관을 추정해 입력하지 않습니다. 공통 한도를 쓰는 항목은 하나의 혜택으로 만들고 KB 받은 혜택명을 여러 줄로 지정합니다.

## 매월 사용

신규 발급 등으로 전월 실적과 다른 구간이 적용되는 달에는 **적용 구간**에서 해당 구간을 선택하고 **적용 구간 저장**을 누릅니다. 해당 월만 변경되며 재동기화 후에도 유지됩니다. 다른 달은 자동 계산합니다. **자동 · 전월 실적 기준**으로 저장하면 직접 지정을 해제합니다. 이는 사용자가 정한 한도로 표시하는 기능이며 KB의 신규 발급 혜택 자격을 자동 판정하지 않습니다. 실제 인정 실적과 다음 달 예상 구간은 변경하지 않습니다.

조회할 월을 선택하고 해당 카드의 **KB 동기화**를 누릅니다. 확장 프로그램 0.4.0과 KB 로그인이 필요합니다. 기존 연결코드는 유지되고 PIN은 저장하지 않습니다.

- KB 월별 실적 화면에서 전월과 당월을 각각 선택하고, 설정된 카드와 조회 버튼을 눌러 인정 실적을 읽습니다.
- 전월 실적은 이번 달 혜택 구간을 결정합니다. 당월 실적은 다음 달 예정 구간과 다음 구간까지 부족한 금액에 사용합니다.
- 받은 혜택 화면에서 선택한 월을 조회합니다. 상세의 번호 페이지를 순서대로 읽고 KB 요약 합계와 상세 합계를 대조합니다.
- 저장한 KB 혜택명·단위와 정확히 일치하는 상세를 합산합니다. 전체 카드의 합계를 해당 카드에 배정하지 않습니다.
- 동기화 결과는 월별로 자동 저장합니다. 다시 동기화하면 해당 월 결과를 교체하므로 중복 합산하지 않습니다. 거래내역이나 자산 잔액은 변경하지 않습니다.

조회가 누락되거나 KB 합계와 맞지 않으면 일부 수집 경고를 표시하고 남은 혜택·사용률은 확정하지 않습니다. 조회되지 않은 실적을 0원으로 처리하지 않습니다. KB에서 제공하지 않는 과거 월은 자동 조회할 수 없습니다. 추가 페이지 묶음을 확인하지 못하면 일부 수집으로 표시합니다.

## 저장과 검증

구간 설정은 kb_benefit_plan에 카드·적용 시작월별로, 수집 결과는 kb_benefit_usage에 카드·조회월별로 저장합니다. 기존의 수동 월별 기록 테이블은 삭제하지 않지만 새 관리 화면은 구간 설정과 동기화 결과를 사용합니다. 원본은 Git에서 제외된 data/kb-card/benefits/에 보관합니다.

`gradlew migrateKbCardImport`로 테이블을 추가하고 앱을 재시작합니다. Node와 브라우저 테스트는 월 선택·카드 조회·상세 페이지 수집 및 설정/동기화 UI를 검증합니다. 서버 테스트는 실적 구간 경계, 전월/당월 분리, 정확한 혜택 매칭, 불완전 수집, 동시 설정 수정, 반복 동기화 시 중복 방지를 검증합니다.
