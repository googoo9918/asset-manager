# 카드 신용공여기간과 예상 청구 명세

## 이용 방법

1. 카드 → 수정 → **신용공여기간 · 결제 대상 이용기간**을 설정합니다.
2. 결제월 기준 마감 월(당월/전월/전전월)과 마감일을 입력합니다. 31은 말일입니다.
   예: 결제일 14일, 전월 말일 마감 → 전월 1일~말일 이용분이 이번 달 14일 청구 예상입니다.
   전월 15일 마감이면 전전월 16일~전월 15일 이용분입니다.
3. 카드 화면의 **결제일별 예상 청구 명세**에서 결제월을 선택합니다.
   소유자 선택을 반영하며, 카드별 이용일·구매액·이번 예상 청구액·회차를 15건씩 표시합니다.
4. 같은 구매를 별도 ‘기존 할부’로 등록했다면 명세의 **원거래 연결**에서 해당 구매를 선택합니다.
   이후 기존 할부 일정만 반영하고 원거래의 자동 계산 회차는 제외합니다.

## 계산과 구분

- 카드사별 기간을 추정하여 자동 입력하지 않습니다. 기존 카드는 미설정으로 유지합니다.
- 한 기간의 시작일은 이전 달 마감일 다음 날입니다. 월말·윤년에는 해당 월 마지막 날로 보정합니다.
- 일시불은 이용일이 속한 기간의 결제월에 전액 배정합니다.
- 할부 구매는 첫 청구월부터 등록 개월 수만큼 분할합니다. 소수 둘째 자리까지 내림하고 마지막 회차에 차액을 더해 구매액과 일치시킵니다.
- 별도로 등록한 기존 할부는 저장된 일정과 납부 상태를 사용합니다. ‘등록 회차’는 잔여 할부를 등록한 이후의 회차입니다.
- 원거래 연결 시 기존 일정 이전의 자동 계산 회차도 제외됩니다. 실제 거래·계좌 잔액·납부 이력은 변경하지 않습니다.
- 취소된 거래와 체크카드 사용은 자동 예상액에서 제외합니다. 연결된 원거래가 취소·수정되면 기존 할부는 자동 취소하지 않고 확인 필요로 표시합니다.
- 기존 할부와 자동 계산 할부가 함께 있고 연결이 미확정이면 중복 여부를 확인하도록 안내하며 차이 계산을 보류합니다.
- 결제계좌와 예정일이 같은 카드들의 예상액을 합산합니다. 실제 출금은 계좌 합산 결제번호별 한 번만 집계합니다.
- 실제 출금과의 차이는 해당 그룹의 결제월 처리가 끝났고, 설정·연결·소유자 조회 범위가 비교 가능할 때만 표시합니다.
- ‘결제월 완료’는 해당 결제월의 출금 처리 상태입니다. 카드사가 해당 전표를 실제로 청구했다는 개별 확인은 아닙니다.
- 휴일 이연은 자동 적용하지 않습니다. 기존 예정 거래에서 출금일을 옮겼다면 그 날짜를 표시합니다.
- 카드사 확정 명세를 수집한 것이 아닙니다. 매입 지연, 할인, 수수료, 부분취소 등은 차이가 날 수 있습니다.
- 현재 등록된 이용내역만 반영합니다. KB 수집 결과는 거래 등록을 마쳐야 명세에 포함됩니다.
- 설정을 바꾸면 과거 예상 명세도 현재 설정으로 다시 계산합니다. 실제 출금 이력은 그대로 유지합니다.

## 스키마

기존 DB에는 `.\gradlew.bat migrateCardBilling`을 적용합니다. 적용 전 백업을 권장합니다.
추가 컬럼은 payment_card.billing_closing_day / billing_month_offset 및 initial_installment.source_entry_id입니다.
기존 값·금액을 변경하지 않으며 반복 적용할 수 있습니다. 새 DB는 db/schema.sql에 포함됩니다.
