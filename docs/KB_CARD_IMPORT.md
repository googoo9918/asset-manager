# KB국민카드 이용내역·매출전표 가져오기

카드 화면의 `KB국민카드 가져오기`에서 사용합니다. **평소 사용하는 Chrome 프로필**에 로그인한 뒤 최초 한 번 확장 프로그램을 등록합니다. 이후 앱이 실행되면 저장된 설정으로 자동 재연결합니다. 기본 수집은 이미 저장된 전표를 재사용하고 새 내역·변경된 내역·실패한 전표만 조회합니다. KB 인증이 만료되면 사용자가 PIN 로그인을 다시 진행해야 합니다.

## 준비

1. Node.js 24 LTS와 Chrome을 설치합니다.
2. 저장소 루트에서 `npm ci --prefix tools/kb-card`를 실행합니다.
3. 기존 DB에는 `db/migrate_kb_card_import.sql`을 적용합니다. 저장소 루트에서 `.\gradlew.bat migrateKbCardImport`를 실행하면 앱의 로컬 DB 설정으로 적용합니다. 새 DB는 `db/schema.sql`에 포함되어 있습니다. 이 테이블은 이미 저장한 원본의 식별자를 보관하며, 기존 거래를 변경하지 않습니다.
4. 앱을 재시작합니다. 실행 위치는 저장소 루트입니다. 다른 위치에서 실행한다면 `application-local.yml`에 아래 설정을 추가합니다.

```yaml
kb-card:
  node: 'C:/Program Files/nodejs/node.exe'
  bridge: 'C:/DEV/asset-manager/tools/kb-card/bridge.cjs'
```

이 작업환경에서는 `build/test-tools/node-v24.19.0-win-x64/node.exe`가 있으면 자동으로 사용합니다. 배포 환경에서는 설치한 Node.js 경로를 지정하세요. `KB_BROWSER_CHANNEL=msedge` 환경변수로 Edge를 선택할 수도 있습니다.

## 사용 흐름

1. Chrome의 `chrome://extensions`에서 개발자 모드 → 압축해제된 확장 프로그램 로드 → 저장소의 `tools/kb-card-extension` 폴더를 선택합니다. 최초 한 번만 필요합니다.
2. 카드 화면 → KB국민카드 가져오기 → KB 로그인 화면 열기. 평소 쓰는 프로필에서 PIN 로그인합니다. KB 이용내역 화면에서 조회 기간을 선택하며, 전체 카드를 조회해도 됩니다.
3. 최초 한 번 앱의 `최초 연결 설정`을 펼쳐 연결코드를 확인합니다. 로그인된 KB 탭에서 확장 프로그램에 코드를 입력하고 연결합니다. 등록 후에는 코드를 다시 입력할 필요가 없습니다. 앱/연결 도구를 재시작하면 최대 약 1분 이내 자동 재연결합니다.
4. `필요한 전표 가져오기`를 누릅니다. 이용내역 목록은 취소·매입 상태 변경을 확인하기 위해 전체 페이지를 읽지만, 저장된 동일 내역의 전표 팝업은 열지 않습니다. 정상/취소 총 건수와 수집 건수를 비교하고, 새로 조회하는 전표는 승인번호를 대조합니다. 페이지 클릭 후 내용이 바뀌지 않거나 건수가 맞지 않으면 완료 처리하지 않습니다. 한 번에 500건까지입니다.
5. 카드별 결제액, 포인트리 결제액, 할인금액, **적립예상** 포인트리와 전표를 확인합니다. 수집 원본은 `data/kb-card/`에 JSON으로 보관되며 `최근 수집 결과`로 다시 볼 수 있습니다. 이 단계에서는 가계부 거래를 쓰지 않습니다.
6. 가계부에 반영하려면 수집된 카드와 앱의 카드를 연결하고 미리보기를 확인합니다. 여러 카드의 내역이 섞여 있으면 선택한 카드의 행만 반영 대상으로 표시합니다. 저장할 행과 지출 분류를 선택합니다. 체크카드는 현재 잔액에 이미 반영됐는지 선택합니다.
7. 자동 재연결을 중단하려면 확장 프로그램의 연결 종료를 누릅니다. 다시 연결할 때는 코드 입력을 비워 두고 연결할 수 있습니다. Chrome 재시작 후 KB 탭이 여러 개여서 원래 탭을 찾을 수 없으면 사용할 KB 탭에서 확장 프로그램의 연결 버튼만 눌러주세요.

확장 프로그램의 새로고침은 확장 **코드가 업데이트될 때만** 필요합니다. 일반적인 수집 작업마다 새로고침하지 않습니다. 기존 0.1.0 개발 버전은 새로고침하여 0.2.0으로 업데이트하고 최초 코드를 한 번 저장해야 합니다.

파일 또는 현재 화면에서 가져오기는 보조 경로입니다. CSV·TSV·XLSX·확장 프로그램 파일을 지원합니다. CSV는 UTF-8/EUC-KR, 파일은 5MB, 표는 2,000행까지입니다. XLS는 Excel에서 XLSX로 변환해주세요. 별도 로그인 창은 기존 프로필 인증을 공유하지 않으므로 기본 흐름에서는 사용하지 않습니다.

## 반영 기준

### 전표 재사용과 조회 방식

- **새로 필요한 전표만**이 기본입니다. 이용일시·카드명·승인번호·상태·금액·가맹점 등을 포함한 원본 행 전체를 대조합니다. 같은 승인번호라도 금액이나 상태가 바뀌면 다시 조회합니다.
- 과거의 정상 완료 수집 파일도 처음 실행할 때 색인화하므로 기존 전표를 처음부터 다시 열지 않습니다. 전표는 `data/kb-card/receipt-cache/`에 보관하며 Git 추적에서 제외됩니다.
- 전표 하나를 조회할 때마다 저장합니다. 이후 페이지 이동 중 실패하거나 도구가 종료되어도 성공한 전표를 다음 수집에서 재사용합니다. 전표 조회 실패 자체는 재사용 대상으로 저장하지 않습니다.
- **이용내역만**은 전표 조회를 생략합니다. **전체 전표 다시 조회**는 원본 행에 변화가 없어도 전표 내용을 재확인할 때 사용합니다.
- 신규 조회·재사용·확인 필요 건수를 별도로 표시합니다. 전표 목록은 검색과 15건 페이징을 제공하고, 전표 상세는 펼칠 때 렌더링합니다. 거래 등록 미리보기도 15건씩 표시하며 페이지를 옮겨도 선택·분류가 유지됩니다.
- 수집 중 창을 닫아도 서버의 작업은 계속됩니다. 다시 열면 진행 중인 작업을 이어서 표시합니다. 수집과 거래 등록은 별도이며, 중복 등록 검증은 유지합니다.

### 거래 등록

- 미리보기에서는 DB에 거래를 쓰지 않습니다. 미리보기는 서버 메모리에 30분간 유지되며 재시작하면 사라집니다.
- 승인번호+이용일(없으면 날짜+가맹점+금액+할부개월)로 카드별 원본 식별자를 만듭니다. 저장 시 잠금 아래 다시 검사하며 중복 요청은 차단합니다.
- 기존 거래에 같은 카드·날짜·금액이 있으면 중복 의심으로 표시하여 자동 저장하지 않습니다. 실제로 서로 다른 결제이면 거래 화면에서 확인해 수동 기록할 수 있습니다.
- 취소, 환불, 미확인 상태, 0원/음수 거래는 확인 대상으로 표시합니다. 원거래 매칭·부분취소 처리는 아직 자동화하지 않았습니다. 기존 거래 화면에서 확인 후 처리합니다.
- 할부는 월 청구액이 아니라 전체 구매액과 총 할부개월을 가져옵니다. 신용카드 이용금액과 실제 카드대금 출금은 기존 앱 규칙에 따라 구분됩니다.
- 포인트리 결제도 미리보기에 표시합니다. `kb_card_mapping`에 KB 이용카드명·앱 체크카드·포인트 자산을 연결하고 `point_payment=true`로 저장한 경우에만 등록할 수 있습니다. 등록 시 연결 자산에서 사용액을 차감하며 카드 사용내역에도 표시합니다. 중복 등록은 차단하며, 수동 거래 취소 시 기존 차감을 복원합니다. 저장된 연결과 카드의 실제 결제계좌가 다르면 등록을 중단합니다.
- 카드 연결은 최초 카드 선택 후 미리보기를 누를 때 `PUT /api/kb-card/mappings`로 DB에 저장합니다. 팝업 재열기·페이지 새로고침·앱 재시작 후에도 `GET /api/kb-card/mappings`로 복원하여 자동 선택합니다. 매핑 저장만으로 거래를 등록하거나 잔액을 차감하지 않습니다. 기존 연결의 변경은 허용하지 않습니다. 원본에 이용 카드명이 없으면 매핑을 저장하지 않습니다.
- 미리보기에서 거래마다 카테고리와 분류 근거를 표시합니다. 저장한 가맹점·업종 규칙을 우선하고, 음식점·커피전문점·주유소·슈퍼마켓 업종 및 승인된 가맹점 예외 규칙을 적용합니다. 판단이 어려운 편의점·백화점·일반 PG 등은 `기타 > 미분류`로 둡니다. 같은 가맹점의 다른 업종은 별개 규칙입니다.
- 수집 전표는 원본 거래 키(이용일시·이용카드명·승인번호·상태)가 유일하게 일치할 때만 업종을 연결합니다. 전표가 없거나 대응이 불명확하면 업종을 추정하지 않습니다.
- 거래별 분류 수정, 분류 일괄 변경, 대분류·중분류 추가가 가능합니다. 분류 추가는 별도로 즉시 저장되지만, `다음부터 동일 가맹점·업종에 적용` 규칙은 최종 거래 등록과 함께 저장합니다.
- 최종 확인창에서 카드·등록 건수·총액·미분류 건수·잔액 차감 대상·저장할 규칙을 확인합니다. 취소하면 거래·규칙·잔액은 변경하지 않습니다. 서버도 `confirmed=true`와 각 선택 거래의 활성 지출 분류를 검증한 뒤 하나의 트랜잭션에서 등록합니다. 무확인 자동 등록은 하지 않습니다.
- 전표미매입/전표매입은 원본 상태를 보존하고 승인 거래로 미리보기합니다.
- 저장된 거래는 기존 거래 화면에서 수정·취소할 수 있습니다. 별도 원본 식별자는 남아 재가져오기를 방지합니다.
- 매출전표는 카드명·승인번호·거래일자·거래유형·매입상태·금액·부가세·봉사료·합계·가맹점 정보를 구조화하여 보관합니다. PDF 파일 보관은 지원하지 않습니다. 일반 XLS 바이너리, 암호화 파일, 해외 통화 환산, 카드 상품별 혜택 규칙·전월 실적 계산은 별도 구현이 필요합니다. 조회 화면의 할인·예상 적립 정보는 카드별로 합산합니다.

## 인증과 데이터

기존 Chrome의 로그인 상태는 Chrome이 관리합니다. 앱과 확장 프로그램은 PIN 입력창·쿠키·인증 응답을 읽거나 저장하지 않습니다. 확장 프로그램은 KB 도메인에만 접근하며, 연결한 탭과 그 팝업만 조회합니다. 연결 도구는 `127.0.0.1:18765`에만 열리고 연결코드와 확장 프로그램 출처를 검사합니다. 연결코드는 `.local/kb-card-pairing.json`과 확장 프로그램의 로컬 저장소에 보관됩니다. 은행 인증정보가 아니라 이 PC의 앱과 확장 프로그램을 연결하는 키입니다. 해당 설정과 수집 원본은 Git에서 제외합니다. 앱 API는 로컬 주소와 동일 출처의 요청만 허용합니다.

별도 로그인 창은 개발/대체 경로입니다. 기본 프로필 인증을 공유하지 않으며 새로운 기기인증을 요청받을 수 있습니다. 일반 Chrome 프로필에 원격 디버깅을 강제로 붙이거나 프로필·쿠키 파일을 복사하지 않습니다. [Chrome 원격 디버깅 제한](https://developer.chrome.com/blog/remote-debugging-port)을 참고하세요.

앱을 원격 서버에 배포하면 로그인 창은 원격 서버에 열립니다. 이번 기능은 앱과 브라우저를 같은 PC에서 사용하는 환경을 대상으로 합니다.

## 검증

```powershell
node tests/page-modules.cjs
node --test tools/kb-card/bridge.test.cjs
node --test tools/kb-card/relay.test.cjs
node --test tools/kb-card/collector.test.cjs tools/kb-card/extension.test.cjs
.\gradlew.bat test --tests com.family.asset.service.KbImportServiceTest
$env:NODE_PATH=(Resolve-Path tools/kb-card/node_modules).Path
$env:PLAYWRIGHT_CHANNEL='chrome'
node tests/browser-smoke.cjs
```

브라우저 도구 테스트는 KB 요청을 전부 가로채 모의 페이지와 다운로드를 제공합니다. 실제 인증 성공이나 보안 프로그램 호환성을 증명하지는 않습니다.

참고: [Playwright 브라우저 실행](https://playwright.dev/docs/api/class-browsertype), [다운로드 처리](https://playwright.dev/docs/downloads), [ExcelJS](https://github.com/exceljs/exceljs).
